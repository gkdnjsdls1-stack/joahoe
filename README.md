## 권한

**멤버와 모임은 관리자가 정합니다.** 설정에서 멤버를 더하거나 빼고, 모임 자체를 새로 만들 수 있습니다. 멤버를 빼도 그 사람이 남긴 👍·한 줄·참석 기록은 지워지지 않고 목록에서만 빠집니다.

**모임마다 주소가 다릅니다.** `.../joahoe/#g=<모임키>` 형태이고, 받은 사람은 자기 모임만 봅니다. 모임 전환기는 관리자에게만 보여서, 다른 모임이 있다는 것도 모릅니다. 설정 → `링크` 에서 지금 고른 모임의 주소를 복사해 그 모임 사람들에게 주세요.

다만 이건 **가리는 게 아니라 안 보여주는 것**입니다. 주소를 뜯어볼 줄 아는 사람이면 다른 모임도 볼 수 있으니, 완전히 막아야 할 내용은 두지 마세요. 기술적으로 막으려면 모임마다 Supabase 프로젝트를 나눠야 합니다.

| | 나 (관리자) | 친구들 |
|---|---|---|
| 우표첩 · 지도 보기 | ○ | ○ |
| 우표 발행, 사진·그림 올리기 | ○ | ✗ |
| 다녀온 가게 수정 (이름 · 링크 · 동네) | ○ | ✗ |
| 우표 지우기 | ○ | ✗ |
| 동네 위치 옮기기 | ○ | ✗ |
| 가고 싶은 곳 추가 | ○ | ○ |
| 가고 싶은 곳 수정 · 접어두기 · 지우기 | ○ | ○ |
| └ 그중 한 줄 이유 | 쓴 사람만 | 쓴 사람만 |
| 👍 찜 | ○ | ○ |
| 한 줄 쓰기 | ○ | ○ |

- **나** — 기기마다 한 번 로그인 (내 폰, 내 컴퓨터)
- **민·수** — 링크를 누르고 `누구세요?` 에서 이름 고르면 끝. 로그인도, 코드도 없음

우표와 사진은 로그인 없이는 손이 닿지 않습니다. `config.js` 의 키가 공개돼도 우표첩은 안전합니다. 열려 있는 건 **가고 싶은 곳(추가 · 수정 · 지우기), 👍, 한 줄** 입니다.

가고 싶은 곳은 셋이 같이 쓰는 목록이라 **지우기까지 열어뒀습니다.** 대신 알아둘 것 — **되돌리기는 없습니다.** 지우면 그 줄의 👍 도 같이 사라지고, 다시 적는 수밖에 없습니다. 지우는 대신 `접어두기` 를 쓰면 목록에서만 빠지고 남아 있습니다. 그리고 이건 **링크를 아는 사람이면 누구나** 할 수 있다는 뜻이기도 합니다 — 주소가 곧 열쇠입니다.

닿는 범위는 거기까지입니다. **다녀온 가게와 우표는 그대로 잠겨 있어서**, 최악의 경우에도 잃는 건 가고 싶은 곳 목록뿐입니다. 데이터베이스도 `wish = true` 인 줄만 열어뒀기 때문에, 가고 싶은 곳을 "다녀온 곳"으로 바꿔치기하는 것도 막혀 있습니다.

`누구세요?` 는 보안이 아니라 **누가 👍 했고 누가 한 줄을 썼는지 표시하는 용도**입니다.

## 설정 — 10분

### 1. Supabase 프로젝트 만들기

1. [supabase.com](https://supabase.com) 가입 → `New project`
2. 이름은 아무거나, **Region은 `Northeast Asia (Seoul)`** 로. 카드 등록 없음
3. 비밀번호(데이터베이스 암호)는 적어두기만 하고 쓸 일은 없습니다

### 2. 테이블과 권한 만들기

1. 왼쪽 메뉴 `SQL Editor` → `New query`
2. [`supabase/schema.sql`](supabase/schema.sql) 전체를 붙여넣고 **Run**
3. `Success` 가 나오면 끝입니다. 여러 번 실행해도 안전합니다

**(b) 저장소 정책 NOTICE가 떴다면** — 프로젝트에 따라 사진 저장소 권한을 SQL로 못 만듭니다. 그때만 손으로 만들면 됩니다.

- `Storage` → `photos` 버킷 → `Policies` → `New policy`
- `SELECT` : 대상 `anon, authenticated`, 조건 `bucket_id = 'photos'`
- `INSERT` · `UPDATE` · `DELETE` : 대상 `authenticated`, 조건 `bucket_id = 'photos'`

### 3. 관리자 계정 만들기

1. 왼쪽 메뉴 `Authentication` → `Users` → `Add user` → `Create new user`
2. 쓸 이메일과 비밀번호를 넣고 **`Auto Confirm User` 를 켠 채로** 만듭니다
3. `Authentication` → `Sign In / Providers` → **`Allow new users to sign up` 을 끕니다**
   — 이걸 꺼야 다른 사람이 계정을 만들어 관리자가 되는 일을 막습니다

### 4. 키 넣기

1. `Project Settings` → `Data API`
2. `Project URL` 과 `anon public` 키를 복사
3. [`config.js`](config.js) 에 붙여넣기

```js
window.JOAHOE_CONFIG = {
  SUPABASE_URL: "https://xxxxxxxx.supabase.co",
  SUPABASE_ANON_KEY: "eyJhbGciOi..."
};
```

### 5. 깃허브 페이지 켜기

1. 이 폴더를 깃허브 저장소에 올립니다 (**Public**)
2. 저장소 → `Settings` → `Pages`
3. `Source` 를 `Deploy from a branch`, 브랜치는 `main`, 폴더는 `/ (root)` → Save
4. 1~2분 뒤 주소가 나옵니다

### 6. 첫 실행

1. 주소를 열면 `셋의 이름을 적어주세요` 가 뜹니다 → 관리자 로그인 후 이름 세 개 입력
2. `누구세요?` 에서 나를 고릅니다
3. 링크를 단톡방에 던집니다. 두 친구는 그냥 열면 됩니다

## 가게 검색 (선택)

가고 싶은 곳을 추가하거나 가게 정보를 고칠 때 **상호로 검색해서 이름·링크·동네를 한 번에 채울 수 있습니다.** 안 켜도 앱은 그대로 돌아갑니다 — 검색 칸이 안 보일 뿐이고, 직접 적으면 됩니다.

1. [developers.kakao.com](https://developers.kakao.com) 로그인 → `내 애플리케이션` → 앱 하나 만들기
2. 앱 관리 페이지 → **`카카오맵` → `사용 설정` → `상태` 를 `ON`**
3. **`JavaScript 키`** 복사 (`REST API 키`가 아닙니다 — 지도 SDK에 REST 키를 쓰면 에러가 납니다)
4. 그 JavaScript 키의 **`JavaScript SDK 도메인`** 에 아래 둘을 등록

   ```
   https://gkdnjsdls1-stack.github.io
   http://localhost:8731
   ```
5. [`config.js`](config.js) 의 `KAKAO_JS_KEY` 에 붙여넣기

앱 만들 때 묻는 **`앱 대표 도메인`은 필수가 아니고, SDK를 열어주는 설정도 아닙니다.** 소개용 정보일 뿐이라 비워도 됩니다. 검색을 동작하게 하는 건 4번의 `JavaScript SDK 도메인` 입니다 — 둘을 헷갈리지 마세요.

카카오는 **180일 동안 설정 변경도 API 호출도 없으면 `장기 미이용 앱`** 으로 돌립니다. 걸리면 앱 관리 페이지에서 풉니다. Supabase는 keepalive가 막아주지만 이건 수동입니다.

**무료 쿼터는 계정 기준 '첫 번째로 카카오맵을 켠 앱' 하나에만 붙습니다.** 이미 다른 앱에서 카카오맵을 쓰고 있다면 새 앱은 비즈월렛 연결과 유료 설정이 필요합니다. 쿼터 사용량은 앱 관리 페이지 `통계` → `쿼터` 에서 봅니다. 한 달에 몇 번 검색하는 수준이라면 무료 범위를 넘길 일은 없습니다.

이 키는 Supabase anon 키처럼 **브라우저에 드러나는 것을 전제로 만든 키**입니다. 보호는 3번의 도메인 등록이 합니다 — 등록한 주소가 아니면 키가 동작하지 않습니다.

**검색은 카카오로 하고 링크는 네이버 지도로** 겁니다 (`https://map.naver.com/p/search/가게이름`). 상호명으로 거는 주소라 같은 이름의 가게가 많으면 엉뚱한 곳이 열릴 수 있습니다. 그때는 링크 칸을 직접 고치면 됩니다.

## 쓰는 법

### 우표 발행 (관리자)

사진 한 장 + 가게 + 음식 이름. 날짜는 오늘, 참석은 전원이 기본입니다. 발행하면 **사진 우표(임시)** 가 꽂히고, 홈에 `그림 기다리는 우표 N장` 이 뜹니다.

### 그림 뽑기

1. 우표를 열고 `🎨 그림 뽑기`
2. **음식 영문 설명**과 **색** 을 채우면 프롬프트가 완성됩니다
3. 지피티에 **기준 우표 + 그날 음식 사진 + 프롬프트** 셋을 넣습니다
4. 나온 그림을 `그림 올리기` 로 올리면 정식 우표가 됩니다

마음에 드는 그림 우표는 열어서 **`기준 우표로 지정`** 하세요. 최대 3장까지 들고 있고, 다음부터 지피티에 함께 첨부하면 스타일이 유지됩니다. 지피티는 새 대화를 열면 스타일이 틀어지기 때문에 이게 중요합니다.

**초반 10장은 한 사람이 전담**해서 뽑는 게 좋습니다. 처음부터 각자 뽑으면 기준이 흔들린 상태로 굳습니다.

### 가고 싶은 곳

누구나 추가하고 👍 할 수 있습니다. **셋 다 👍 하면 만장일치**가 되어 맨 위에서 반짝입니다. 그게 다음 약속이 됩니다. 반대 버튼은 없습니다.

목록은 **`가게` 와 `메뉴` 로 나뉩니다.** 「성수 타코집」처럼 집을 찍어둔 것과 「마라탕」처럼 먹고 싶은 것만 적어둔 것은 다음 약속을 정할 때 쓰임이 다르기 때문입니다. 만장일치는 둘을 가리지 않고 맨 위 `★` 로 올라옵니다.

**고치고 지우는 것도 누구나** 합니다. 카드의 `⋯` 를 누르면 이름·링크·동네를 고치거나, `접어두기`·`이 추천 지우기` 를 할 수 있습니다. 지우면 👍 도 함께 사라지고 되돌릴 수 없으니, 애매하면 접어두세요. 다녀온 가게는 우표가 걸려 있어서 관리자만 고칩니다.

**한 줄 이유만은 쓴 사람 것입니다.** 추천한 사람에게만 입력칸이 뜨고, 남이 열면 「`남역, 튤립` — 김현수 이(가) 쓴 줄이라 그대로 둡니다」 로 보이기만 합니다. 남이 이름·링크·동네를 고쳐 저장해도 그 줄은 건드려지지 않습니다. 다만 `누구세요?` 는 보안이 아니라서 **이름만 바꿔 고르면 넘어갈 수 있습니다** — 막는 장치가 아니라 예의에 가깝습니다. 관리자도 예외가 아닙니다(대신 줄 자체를 지울 수는 있습니다).

90일 넘게 안 가면 `N개월째 안 감` 라벨이 붙고, 오래된 것은 `접어두기` 로 치울 수 있습니다(삭제 아님).

### 뭐 먹지 — 메뉴 추천

가고 싶은 곳 탭의 `🎲 뭐 먹지` 는 **가게가 아니라 메뉴를 골라줍니다.** 가게는 메뉴를 정한 다음에 고르면 됩니다.

- 메뉴 목록은 앱 안에 적혀 있습니다. **카카오 키가 없어도 돌아갑니다**
- 우표에 적은 음식 이름과 맞춰 `3주 전 먹음` 을 붙이고, 기본은 **아직 안 먹어본 것만** 보여줍니다 (`먹어본 메뉴도 보기` 로 전부 펼칩니다)
- `🎲 하나만 뽑기` 는 보이는 것 중에서 하나를 뽑습니다. 방금 뽑은 건 빼고 뽑습니다
- `＋ 담기` 하면 가고 싶은 곳에 **메뉴 줄**로 들어갑니다. 👍 와 만장일치는 가게와 똑같고, 셋 다 👍 하면 그게 다음 약속 메뉴입니다
- 메뉴 줄은 링크도 동네도 없어서 **지도에는 찍히지 않습니다**
- 목록에 없는 메뉴는 아래 칸에 직접 적어서 담습니다

**메뉴 밑에 가게를 묶습니다.** 담아둔 메뉴를 누르면 `이 메뉴를 먹을 가게` 칸이 있고, 거기서 `가게 찾기` 로 상호를 찾아 고르면 그 메뉴 밑으로 들어갑니다. **같은 메뉴에 가게 둘을 담으면 한 메뉴 아래 나란히 묶입니다** — 「마라탕」 하나에 마라탕집 둘이 딸리는 식입니다. 이미 가고 싶은 곳에 있던 가게를 고르면 새로 만들지 않고 그 메뉴 밑으로 옮깁니다.

묶인 가게는 **보통 가게와 똑같습니다** — 각자 👍 를 받고, 동네가 있으면 지도에도 찍힙니다(메뉴 줄만 안 찍힙니다). `묶기 풀기` 를 누르면 가게 목록으로 올라오고, 메뉴를 지워도 **딸린 가게는 사라지지 않고** 가게 목록으로 올라옵니다.

「언제 먹었는지」는 우표에 적은 음식 이름을 글자로 맞춘 것이라 가끔 틀립니다. 맛 순위는 아닙니다.

**쓰던 데이터베이스라면 [`supabase/schema.sql`](supabase/schema.sql) 을 한 번 더 Run 해주세요.** 두 가지가 바뀌었습니다.

- 메뉴 줄을 가리는 `kind` 칸 — 안 돌려도 담기는 되지만, 메뉴가 그냥 가게 한 줄로 들어가서 지도에 섞입니다
- 메뉴 밑에 가게를 묶는 `parent_id` 칸 — 안 돌리면 묶이지 않고 가게가 따로 담깁니다
- 친구들의 **가고 싶은 곳 수정·삭제 권한** — 이건 안 돌리면 아예 안 됩니다. 버튼은 보이는데 누르면 `관리자만 할 수 있어요` 가 뜹니다

### 지도

가게마다 **링크**와 **동네**를 적으면 동네별로 점이 찍힙니다. 다녀온 곳은 파란 점, 가고 싶은 곳은 빨간 점, 만장일치는 바깥에 링이 하나 더. 점을 누르면 가게 카드가 뜹니다.

실제 지도 타일은 쓰지 않습니다. **동네 이름을 끌어다 배치**하면 그 묶음이 통째로 움직이고, 새 가게는 알아서 제 동네로 들어갑니다. 위치는 셋이 함께 쓰는 값입니다.

## 고칠 때

이 폴더를 고쳐서 깃허브에 올리면 1~2분 뒤 반영됩니다. 빌드 과정은 없습니다.

```bash
powershell -ExecutionPolicy Bypass -File serve.ps1
```

파일을 열어서 바로 보면(`file://`) 안 됩니다. Supabase 연결이 막힙니다.

## 알아둘 것

**Supabase 무료 프로젝트는 일주일 동안 아무도 안 들어가면 일시정지됩니다.** 한 달에 한 번 모이는 우리에게는 거의 항상 멈춰 있다는 뜻이라, 친구가 링크를 눌렀을 때 안 열리고 당신이 대시보드에서 깨워야 합니다.

그래서 `.github/workflows/keepalive.yml` 이 **사흘마다 한 번 가볍게 찔러서** 깨어 있게 합니다. 저장소를 올리면 자동으로 돕니다. 따로 설정할 것은 없습니다.

한 가지만 — **깃허브는 저장소에 60일 동안 아무 변화가 없으면 예약 작업을 꺼버립니다.** 그러면 `Actions` 탭에 다시 켜라는 배너가 뜹니다. 버튼 한 번 누르면 됩니다.

**사진은 관리자만 올립니다.** 민·수가 더 잘 찍었으면 단톡방으로 보내주면 당신이 올립니다.
